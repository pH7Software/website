Currently, the way how pH7CMS is versioning might not always make sense.

That's why from pH7CMs 3 (to avoid confusions with the current versioning scheme). will be versioned according to the following format: <i>MAJOR.MINOR.PATCH </i>.

I got the inspiration from the famous <a href="https://semver.org/spec/v2.0.0.html" rel="noopener noreferrer">Semantic</a> versioning system.

SenVer is best for APIs. That's why I changed a little bit the rules to fit perfectly with "<strong><a href="/">pH7 Social Dating CMS</a></strong>".

<h3>How Works The New Versioning System...?</h3>
Given a version number
<strong>MAJOR.MINOR.PATCH</strong>, increments the:
<ol>
   <li><strong>MAJOR</strong> version when pH7CMS gets new features or new modules/new framework packages.</li>
   <li><strong>MINOR</strong> version when pH7CMS gets minor enhancements or improvements (such as design improvements or better UX.</li>
   <li><strong>PATCH</strong> version when pH7CMS get bug fixes.</li>
</ol>
Additional labels for pre-release and build metadata are available as extensions to the MAJOR.MINOR.PATCH format.

Hope this new pH7CMS's versioning scheme will help you better to know if it gets new features, enhancements or just bug fixes.
